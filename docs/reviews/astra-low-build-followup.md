# Astra-low 빌드 참조 후속 검토

2026-10-21. 아래는 주 에이전트가 정리한 독립 검토 응답과 수정 결과입니다.
검토 모델은 gpt-6-astra, reasoning effort는 low입니다.
기존 3차 번역 품질 판정은 그대로 유지합니다.

## 범위

- `scripts/PublicizeReferences/Program.cs`, 프로젝트 참조 및 `IsekaiMod.Local.csproj`.
- 공개화 사본 생성의 안전성, 원본 보존, 기본·추가 참조 충돌 가능성을 검토했습니다.
- 리뷰어는 게임 PC에 접속하거나 빌드를 직접 실행하지 않았습니다.
  빌드 결과는 주 에이전트의 실행 기록이며 실기 검증이 아닙니다.

## 발견과 처리

1. 기존 출력 존재 검사와 쓰기 사이의 경쟁 조건을 지적했습니다.
   `FileMode.CreateNew` 스트림으로 출력하도록 고쳤습니다.
   실제 PC 원본으로 재생성한 공개화 DLL 해시는 수정 전과 같습니다.
2. Assembly-CSharp·TTT 외에는 두 참조 폴더의 중복 DLL을 자동 검출하지 않는다고 지적했습니다.
   두 주요 DLL은 명시적으로 제외하며, 나머지 추가 폴더에는 기본 폴더와 중복된 DLL을
   두지 않아야 한다는 운영 제한을 빌드 문서에 명시했습니다.
   현재 성공 빌드는 추가 폴더 없이 하나의 검증된 overlay를 사용합니다.

## 재검토 결론

리뷰어는 두 권고가 적절히 처리되었고, 자체 캐시·TTT 우선 선택이 명시적인
사용자 경로 설정과 제외 규칙을 보존한다고 확인했습니다.
새 승인 차단 문제는 없었습니다. 다만 일반적인 참조 중복은 자동 검사하지 않으며,
문서화된 운영 제한에 의존합니다.

## Key Learnings:

1. 기존 파일을 덮어쓰지 않는 도구는 출력 스트림 자체를 CreateNew 모드로 열어야 합니다.
2. 참조 준비와 전체 빌드 성공은 원격 설치나 실제 게임 검증을 대신하지 않습니다.
